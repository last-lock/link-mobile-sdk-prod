class BlueLink(iOSIHeartbeatParser: IHeartbeatParser?)

BlueLink class - Acts as an interface between the BlueLink library and implementers.

Handles device discovery, connection management, and BLE read/write operations, abstracting the details of BLE communication and fragmentation.

If a read or write operation is performed for a characteristic that is not present in the device, an appropriate BlueLinkOpFailReason will be returned. Implementation on handling of these failed scenarios is left up to the implementors. Once the implementor has handled the failing operation, it must call completeOperation() to mark the failed operation as complete

readManufacturingSample
Link copied to clipboard
fun readManufacturingSample(peripheral: BluetoothDevice): BlueLinkOperationError?

Issues a single GATT read on the manufacturing data characteristic (6C4D, see UUIDUtils.ManufacturingCharUUID). Results are delivered to BlueLinkEventListener.onCharacteristicRead after BlueLinkPeripheralListenerImpl routes 6C4D payloads without treating them as heartbeat protobuf. The Android manufacturing bridge polls this on a fixed interval (e.g. 100ms), buffers payloads, and sends them to the Pi in one batch when the manufacturing session ends.

fun setManufacturingSession(deviceId: UInt, active: Boolean)

Manufacturing / bench capture: When active is true, marks the tracked lock so BlueLink behaves like a “connection requested” session: DTQHandlers will not auto-disconnect when the operation queue is empty (same idea as a lock asking to stay connected via advertisement).
